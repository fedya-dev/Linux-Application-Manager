# Linux Application Manager

[![GitHub](https://img.shields.io/badge/GitHub-Linux--Application--Manager-181717?logo=github)](https://github.com/fedya-dev/Linux-Application-Manager)
[![Platform](https://img.shields.io/badge/Platform-Debian%20%7C%20Ubuntu%20%7C%20Linux%20Mint-77216F?logo=linux)](https://github.com/fedya-dev/Linux-Application-Manager)
[![Shell](https://img.shields.io/badge/Shell-Bash-4EAA25?logo=gnubash&logoColor=white)](https://www.gnu.org/software/bash/)

Интерактивен Bash скрипт за лесно инсталиране, премахване и управление на полезни програми в **Debian**, **Ubuntu** и **Linux Mint**.

Скриптът предлага цветно терминално меню, инсталиране на приложения по категории, управление на AppImage файлове, системно обновяване, почистване на временни файлове и запис на операциите в лог файл.

> **Важно:** Не стартирайте скрипта директно със `sudo`.  
> Той сам ще поиска администраторска парола само когато това е необходимо.

---

## Възможности

- Интерактивно терминално меню на български език
- Инсталиране на програми по категории
- Премахване на програми чрез отделно меню
- Потвърждение преди деинсталиране
- Обновяване на системата
- Почистване на временни инсталационни файлове
- Показване на основна системна информация
- Автоматично създаване на нужните директории
- Запис на операции и грешки в лог файл
- Поддръжка на Debian, Ubuntu и Linux Mint
- Инсталиране на Brave чрез официално APT хранилище
- Инсталиране на AnyDesk чрез официално APT хранилище
- Изтегляне и управление на AppImage приложения
- Използване на XDG директории за логове и кеш

## Поддържани системи

Скриптът е предназначен за Linux дистрибуции, базирани на Debian:

- Debian
- Ubuntu
- Linux Mint
- Pop!_OS
- Zorin OS
- elementary OS
- Други Debian/Ubuntu-базирани дистрибуции

За правилна работа са нужни:

- Bash
- `sudo`
- `apt-get`

- 64-битова система за Google Chrome, Brave и някои AppImage приложения

## Инсталация

### 1. Клониране на проекта

```bash
git clone [https://github.com/fedya-dev/Linux-Application-Manager.git](https://github.com/fedya-dev/Linux-Application-Manager.git)
```

### 2. Влизане в папката

```bash
cd Linux-Application-Manager
```

### 3. Даване на права за изпълнение

```bash
chmod +x linux-app-manager.sh
```

### 4. Стартиране

```bash
./linux-app-manager.sh
```

Не използвайте:

```bash
sudo ./linux-app-manager.sh
```

Правилният начин е:

```bash
./linux-app-manager.sh
```

При нужда скриптът автоматично ще поиска паролата за `sudo`.

## Файлове и директории

Скриптът използва XDG Base Directory структура за логове и временни файлове.

При стандартна Linux конфигурация файловете се намират в следните директории:

```text
~/.local/state/linux-app-manager/logs/install.log
~/.cache/linux-app-manager/downloads/
~/Applications/
```

| Път | Предназначение |
|---|---|
| `~/.local/state/linux-app-manager/logs/install.log` | Лог на операции, инсталации и грешки |
| `~/.cache/linux-app-manager/downloads/` | Временно изтеглени `.deb` и AppImage файлове |
| `~/Applications/` | Инсталирани AppImage приложения |
| `~/.config/linux-app-manager/` | Запазено място за бъдещи настройки |

### Преглед на лога

Показване на целия лог:

```bash
less ~/.local/state/linux-app-manager/logs/install.log
```

Показване на последните 50 реда:

```bash
tail -n 50 ~/.local/state/linux-app-manager/logs/install.log
```

Наблюдение на лога в реално време:

```bash
tail -f ~/.local/state/linux-app-manager/logs/install.log
```

## AppImage приложения

Nextcloud Desktop и Viber се изтеглят като AppImage файлове в:

```text
~/Applications/
```

Примерно стартиране на Nextcloud Desktop:

```bash
~/Applications/Nextcloud-x86_64.AppImage
```

Примерно стартиране на Viber:

```bash
~/Applications/viber.AppImage
```

Ако е инсталиран AppImageLauncher, скриптът се опитва автоматично да интегрира AppImage приложението в системното меню.

## Безопасност

- Не стартирайте скрипта като `root`.
- Преглеждайте кода преди изпълнение, особено ако сте го изтеглили от fork или непознат източник.
- Скриптът използва `sudo` само при инсталация, премахване на пакети, системно обновяване и добавяне на APT хранилища.
- Преди деинсталиране се изисква потвърждение.
- Логът не съдържа пароли, но може да съдържа имена на пакети, изпълнени команди и системна информация.
- Преди промени по дялове чрез GParted направете резервно копие на важните файлове.
- Преди системно обновяване или масово премахване на пакети е добра идея да имате моментна снимка с Timeshift или друго работещо резервно копие.
